Abstract

Hospital information systems rarely offer programmatic access, but every one of them has a screen. Computer-use agents operate software the way a person does: they read screenshots and use mouse and keyboard, following instructions in natural language. In a preliminary study of three off-the-shelf agents in HospitalRun, an open-source hospital information system, single interactions were reliable, while multi-step workflows across several screens failed far more often, mostly through planning errors. The harness shown here is our follow-up. It takes most of the work away from the large model: a planner writes the steps for the screen in front of it and is called a few times per request, a decision model answers short questions such as which button leads to the right view in a fraction of a second, and plain code does the clicking, the typing and the checking. A step counts as done only when its result is read back from the screen. The harness needs nothing from the application but its screen, and it can run on self-hosted models alone.

How it works

Models decide what to do. Code does it, and reads from the screen whether it worked.

On the workstation next to the clinical software, without a language model

Text recognition
Reads all text in the window at every look at the screen. After an action it reads only the parts that changed.
Detector
Finds controls that carry no text, such as empty fields and icons. It runs only when a step needs it.
Code
Finds a field from its label, clicks, types, and checks every entry on screen. A value that lands next to the wrong label is taken out again.

On a model server self-hosted, reached over the network

Decider
A decision model. It answers a short question with one of the given options and a probability: which click leads to the right view, do the planned steps still fit, is the request complete?
Planner
A chat model that reads images. It writes the steps for the screen in front of it, and a new plan when a step fails or the screen surprises. It is called a few times per request, not for every step.

The models are exchangeable. The planner can be any chat model that reads images behind a chat-completions API, for example Qwen3.8, Gemma 4 or Mistral Small 4. The decider is a decision model such as Clef or d3; without one, the planner’s model decides as well. Text recognition is RapidOCR, the detector a YOLO11m trained on screenshots.

Where off-the-shelf agents struggle

The starting point of the harness: three off-the-shelf computer-use agents on eight routine tasks in HospitalRun with synthetic patient data, ten runs per task and agent.

  • Basic tasks98%success, such as changing a single field
  • Multi-step workflows69%success, such as requesting a medication
  • Main cause of failurePlanningin 29 of the 40 unsuccessful runs, out of 240 in total; the other 11 were visual perception errors

From our manuscript, currently under review; numbers may still change. The task prompts are in tasks.json.
